# TikTok フェーズ判定（AI で再生数を調べてフェーズ分け・サマリー・社内アプリ）

REALITY版・ミクチャ版と同じ形の TikTok 版です。`TIKTOK_フェーズ.gs` を新しい Google スプレッドシートに貼るだけで、シートと社内アプリが揃います。
フェーズの基準は「【原本】SNS_フェーズ表」のマニュアルと同じです（所属者データは使っていません）。

## しくみ

1. 「フェーズ判定」シートに 名前・担当者・TikTokのURL（任意でInstagramのURL）を入れる
2. メニュー「AIで再生数を調べてフェーズ判定」を押すと、1人ずつ次を行う
   - TikTokのプロフィールページから フォロワー・いいね総数・投稿数（累計）を読む（読めないときは飛ばす）
   - Gemini（URLを開く機能＋Google検索）に、直近30日の投稿数・平均再生（投稿3日未満は除く）・最終投稿日を調べてもらう
   - その数字から、下の基準でフェーズを決める（AIが勝手にフェーズを決めないので、毎回同じ基準になる）
3. 有償案件・本部長承認・フェーズ外は ○ を手入力。平均再生・投稿数を手入力すると AI の値より優先
4. 毎月1日に自動で全員を判定し、「判定履歴」に前月分として記録（前月フェーズ・昇格／降格・月別推移に使う）

| フェーズ | 条件 |
|---|---|
| フェーズ4（最終形） | 平均再生20万回以上 |
| フェーズ3（案件化期） | 平均再生10万回以上 または 有償案件○、かつ本部長承認○ |
| フェーズ3候補 | フェーズ3の条件を満たし、本部長承認待ち |
| フェーズ2（成長期） | 週3本以上投稿（30日の投稿数×7÷30） |
| フェーズ1（初期） | 週3本未満 |
| フェーズ外（LTV枠） | 担当者が○を入れた人（人数に数えない） |
| 未判定 | 再生数・投稿数が未集計 |

基準の数字（20万・10万・週3本）と Gemini のモデル名は「設定」シートで変えられます。

## セットアップ（1回だけ）

1. 新しいスプレッドシートを作り、「拡張機能 → Apps Script」に `TIKTOK_フェーズ.gs` を全文貼り付けて保存
2. プロジェクトの設定でタイムゾーンを「(GMT+09:00) 東京」にする
3. 関数 `setupTikTok` を実行して権限を許可する（マニュアル・サマリー・タレント分け・フェーズ判定・判定履歴・設定・取得ログを作る）
4. Google AI Studio（aistudio.google.com）で Gemini の APIキーを発行し、メニュー「TikTokフェーズ → Gemini APIキーを設定」で入れる（スクリプトのプロパティに保存され、シートには書かれない）
5. メニュー「毎月の自動判定をオンにする」
6. アプリ：「デプロイ → 新しいデプロイ → ウェブアプリ」、実行ユーザー＝自分、アクセス＝株式会社LIV 内の全員

## 注意

- TikTok のページは Google のサーバーから読めないことがあります。そのときは AI だけで調べ、取得状況に「ページの数字は取得できずAIのみ」と出ます
- AI が数字を確かめられないときは空欄（未判定）になります。「AIの確度」が低い人は、数字を確認して手入力してください
- 1人10〜20秒かかります。6分の制限に近づくと、残りは1分後に自動で続きを実行します

## アプリの画面を直すとき

`webapp/App.html` を編集して `node tiktok-phase/build.js` を実行すると、`TIKTOK_フェーズ.gs` の `TK_APP_HTML_` に埋め込まれます。

## テスト

node --test tiktok-phase/tests/*.test.js
