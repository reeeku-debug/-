# REALITY ティア判定ツール（日次CSV取込・自動ティア分け・月別ティア）

スプレッドシート「REALITY_ティア判定_週次KPI」に組み込む Apps Script です。
マニュアルシートにある「同梱の REALITY_日次取込.gs」がこれにあたります。

## できること

| やること | 動き | 更新されるシート |
|---|---|---|
| 毎日のCSV取込 | ドライブの取込フォルダにあるCSVを毎日10時に自動で取り込む。メニューからPCのCSVを直接アップロードすることもできる | 取込ログ・日次RAW・月次RAW・タレントマスタ |
| 自動ティア分け | ティア判定のID列を最新月の在籍者に入れ替える。あとはシートの数式が計算する | ティア判定・タレント分け・サマリー・週次KPI |
| 月別のティア確認 | 「月別ティア」のB3で月を選ぶと、その月のT1〜T5のメンバーを前月比つきで表示する | 月別ティア・月別ティア明細 |
| ティア推移 | 取込のたびに、全月を設定シートの基準で判定し直す | ティア推移 |

- 日次RAW には、前回のCSVとの差分（その日に増えた配信時間・ギフトなど）を記録します。CSVを1日入れ忘れても、次のCSVとの差分にまとめて入ります。
- 同じ期間のCSVは「新しいデータなし（重複）」として取り込みません。取込済みより古い期間のCSVもスキップします（増分がマイナスになるのを防ぐため）。
- 月次RAW のその月の行は、最新の累計で上書きします。

## セットアップ（管理者が1回だけ）

1. CSV を入れるフォルダを Google ドライブに作り、URL の `folders/` の後ろ（フォルダID）を控える
2. スプレッドシートの「拡張機能 → Apps Script」を開き、`REALITY_日次取込.gs` の中身を貼り付けて保存する
3. コード先頭の `FOLDER_ID` にフォルダIDを貼り付ける。「プロジェクトの設定」でタイムゾーンを「(GMT+09:00) 東京」にする
4. 関数 `setupTrigger` を実行して権限を承認する
   - 毎日10時に自動で取り込むようになります
   - ティア判定シートの数式の不具合も同時に修正します（下記）
5. スプレッドシートを開き直すと、メニューに「REALITY取込」が出る

## 毎日の使い方

- **自動**：REALITY のCSV（ファイル名 `streamer_開始日_終了日.csv` のまま）をフォルダに入れる。10時に取り込まれる
- **手動**：メニュー「REALITY取込 → CSVをアップロードして取込…」でCSVを選んで「取り込む」を押す（複数ファイルを選べる）
- 結果は「取込ログ」で確認できる（OK・重複・エラーの理由が出る）

## 月ごとのティアの見方

- **月別ティア**：B3（黄色）のプルダウンで月を選ぶ。その月を評価月として判定したメンバーをティアごとに並べる（売上順）
  - 上段：ティアごとの人数、前月の人数、増減、昇格・降格・新規の人数
  - 下段：ティアごとのメンバー。「前月」列は前月のティア（`T3↑`＝前月T3から昇格、`T2↓`＝前月T2から降格）
- **月別ティア明細**：同じ月の全員の数値（配信時間・イベント数・売上・3ヶ月平均・判定理由・次のティアまでなど）。フィルタで担当者やティアを絞り込める
- **ティア推移**：全月のティアの人数と、タレントごとの月別ティア
- 基準（60h・5回・50万/30万/10万・救済ON/OFF）は「設定」シートの値を使う。基準を変えたらメニュー「月別ティアを更新」「ティア推移を再計算」を実行する

## CSVの列名

列名の候補はコード先頭の `COLUMN_ALIASES` にあります。REALITY のCSVの列名が違って
「エラー：列が見つかりません」と出た場合は、エラーに表示されるCSVの列名を `COLUMN_ALIASES` に追加してください。

- 必須：ID・配信者名・配信時間・ギフト金額（「合計ギフト金額」）
- 配信時間：数値（時間）、`12:34:56`、`1時間23分` に対応。列名に「分」「秒」があれば時間に換算する
- イベント数：数値ならそのまま。「参加中のイベント」がイベント名の一覧なら件数を数える（改行・カンマ・読点区切り）
- 文字コード：UTF-8 と Shift_JIS に対応

## ティア判定シートの数式の不具合（setupTrigger で自動修正）

ティア判定シートの Q列（デビュー3ヶ月内の最高月売上）と U列（T4の期限）は、デビュー月が
**11月・12月** のとき「デビュー月＋2ヶ月」を `F+88`（例：202511 → 202599）で計算していて、
3ヶ月目（翌年1月・2月）の売上が反映されていませんでした。正しくは `F+90`（202511 → 202601）です。
`setupTrigger` を実行すると、この部分を書き換えて修正します（何度実行しても安全）。
月別ティア・ティア推移は、最初から正しい計算で判定します。

## テスト

```bash
node --test reality-tier/tests/*.test.js
```

テスト運用シートのテストケース（初回取込・差分・重複・抜けた日・月次RAWの上書き・月またぎと新人追加）を、
スプレッドシートのモックで確認しています。判定ロジックは、実データ（2025/5〜2026/8）で
ティア推移シートの全4,645件と一致することを確認済みです。
